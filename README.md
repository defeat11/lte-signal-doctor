# lte-signal-doctor

[English](README.en.md)

**قراءات راديو خام من مودم LTE ← لوحة حية لشبكة البيت، تجارب ترددات ما تقطع النت، وتوقّع لجودة الإشارة.**

أداة بايثون تراقب مودم LTE في البيت وتشخّص أعطاله.
شغّلتها على مودمي فجمعت **1,925,871 قراءة إشارة في 15 يوم**، وقاعدة SQLite صارت 532 ميغابايت.
البرنامج يدخل على واجهة المودم بنفسه، يقرأ الإشارة كل كم ثانية، ويعرضها في لوحة تفتحها من أي جهاز في البيت.

## المشكلة

نت البيت كله ماشي على مودم LTE واحد.
جودته تتغير من ساعة لساعة: ping ممتاز الصبح، وتقطيع مزعج بالليل.
واجهة المودم الرسمية تعطيك رقمين بس، وما تحفظ أي تاريخ.
فما تقدر تجاوب على أسئلة مثل: أي تردد أفضل وقت اللعب؟ والمشكلة من البرج ولا من الـ Wi-Fi؟

## كيف يشتغل

```
Playwright يسجل الدخول لواجهة المودم (مرة واحدة لكل جلسة)
        │
        ▼ سحب XML للإشارة عبر API المودم مع توكن CSRF
modem_analyzer.py ── حلقة قراءة ──► SQLite (WAL) + CSV + metrics.json
        │
        ▼ خادم HTTP محلي بـ 39 مسار API
dashboard.html (4,053 سطراً، ملف واحد) على أي جهاز في الشبكة
        │
        ▼ طبقات فوق البيانات
تنبؤ SINR │ مؤشر ضغط البرج │ تنبيهات تيليجرام │ طبيب AI │ مختبر الترددات
```

المستودع فيه 6,114 سطر بايثون موزّعة على 19 ملف:

| الملف | الدور | الأسطر |
|---|---|---|
| modem_analyzer.py | حلقة القراءة، الخادم المحلي، ومختبر الترددات | 3,076 |
| dashboard.html | اللوحة كلها في ملف واحد، بدون أي مكتبة خارجية | 4,053 |
| signal_db.py | تخزين SQLite ومقارنة الترددات ببعض | 530 |
| web_diagnostics.py | يفرّق: التقطيع من شبكة البيت، ولا من الراديو، ولا من المشغّل | 281 |
| telegram_alerts.py | ينبّهك إذا طاحت الإشارة، ويرسل تقرير يومي | 258 |
| signal_predictor.py | يتوقّع SINR بعد 3 دقائق بـ machine learning | 237 |
| ai_doctor.py | تشخيص تلقائي عن طريق أي CLI لنموذج AI | 229 |
| tower_insights.py + network_intelligence.py | مؤشرات تقدر تفهم من وين جت، محسوبة من التاريخ المسجّل | 335 |

نموذج التوقّع Gradient Boosting، تدرّب على 3,345 عينة حقيقية.
متوسط خطأه المطلق 0.694 ديسيبل وهو يتوقّع SINR بعد 3 دقائق.
مؤشر ضغط البرج ما يخترع عدد مستخدمين — المودم أصلاً ما يعطيه. بدل رقم مزيف، المؤشر يوريك من وش تكوّن (CQI و SINR و RSRQ).

## أهم قرار في التصميم

**المشكلة:** تغيير تردد المودم يمشي على نفس الوصلة اللي التغيير نفسه ممكن يقتلها.
تردد غلط يعني النت راح، وما فيه طريقة ترجّعه وأنت بعيد.

**القرار:** كل تجربة تردد تعدّي على `guarded_band_experiment`.
يحفظ الإعداد الأصلي، يطبّق التغيير، وبعدها يراقب رجوع الاتصال فعلياً مدة 90 ثانية.
الرجوع للإعداد القديم يصير داخل `finally`، مع إعادة محاولة وتأكّد، فيشتغل حتى لو ماتت جلسة المودم وسط التطبيق.

**التكلفة/العائد:** كل تجربة تاخذ وقت أطول، يوصل دقيقة ونصف.
المقابل: ما يعلق المودم على تردد ميت وأنت برا البيت.

## التشغيل

```
pip install -r requirements.txt
playwright install chromium
copy .env.example .env    ثم املأ عنوان بوابة المودم وكلمة المرور
run_project.bat
```

كلمة مرور المودم وعنوانه في `.env` فقط، ولا واحد منهم مكتوب داخل الكود.
تفتح اللوحة على `http://<عنوان-جهازك>:8000/dashboard.html` من أي جهاز في الشبكة.
`allow_firewall.bat` يفتح المنفذ لباقي الأجهزة، و`watchdog.bat` يعيد التشغيل إذا علّق البرنامج.

إثبات إنه يشتغل — 5 اختبارات smoke تشتغل بدون مودم وبدون أي مكتبة خارجية:

```
$ python smoke_test_db.py && python smoke_test_tower_insights.py &&
  python smoke_test_intelligence.py && python smoke_test_stability.py &&
  python smoke_test_telegram.py
SMOKE OK
TOWER INSIGHTS SMOKE OK
INTELLIGENCE SMOKE OK
STABILITY SMOKE OK
SMOKE TG OK
```
