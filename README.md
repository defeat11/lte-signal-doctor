# lte-signal-doctor

[English](README.en.md)

**قراءات راديو خام من مودم LTE ← لوحة حية للشبكة المنزلية، تجارب ترددات آمنة، وتنبؤ بجودة الإشارة.**

نظام مراقبة وتشخيص لمودم LTE منزلي، مبني بلغة بايثون.
جمع في تشغيل حقيقي **1,925,871 قراءة إشارة خلال 15 يوماً**، في قاعدة SQLite بلغ حجمها 532 ميغابايت.
البرنامج يسجل الدخول لواجهة المودم بنفسه، يقرأ الإشارة كل بضع ثوانٍ، ويعرض كل شيء على لوحة واحدة تفتح من أي جهاز في البيت.

## المشكلة

الإنترنت في البيت كله يمر عبر مودم LTE واحد.
جودته تتقلب بين ساعة وأخرى: بينج ممتاز صباحاً، وتقطيع مزعج مساءً.
واجهة المودم الرسمية تعرض رقمين فقيرين ولا تحفظ أي تاريخ.
فلا يمكن الإجابة عن أسئلة مثل: أي تردد أفضل لوقت الألعاب؟ وهل المشكلة من البرج أم من الواي فاي؟

## كيف يشتغل

```
Playwright يسجل الدخول لواجهة المودم (مرة واحدة لكل جلسة)
        │
        ▼ سحب XML للإشارة عبر API المودم مع توكن CSRF
modem_analyzer.py ── حلقة قراءة ──► SQLite (WAL) + CSV + metrics.json
        │
        ▼ خادم HTTP محلي بـ 39 مسار API
dashboard.html (4,053 سطراً، ملف واحد) على أي جهاز في الشبكة
        │
        ▼ طبقات فوق البيانات
تنبؤ SINR │ مؤشر ضغط البرج │ تنبيهات تيليجرام │ طبيب AI │ مختبر الترددات
```

المستودع 6,114 سطر بايثون في 19 ملفاً:

| الملف | الدور | الأسطر |
|---|---|---|
| modem_analyzer.py | حلقة القراءة، الخادم المحلي، مختبر الترددات | 3,076 |
| dashboard.html | اللوحة كاملة في ملف واحد بلا تبعيات | 4,053 |
| signal_db.py | تخزين SQLite ودراسات مقارنة الترددات | 530 |
| web_diagnostics.py | تمييز التقطيع: وصلة محلية أم راديو أم مشغل | 281 |
| telegram_alerts.py | تنبيهات انهيار الإشارة وتقرير يومي | 258 |
| signal_predictor.py | تنبؤ SINR بعد 3 دقائق بالتعلم الآلي | 237 |
| ai_doctor.py | تشخيص آلي عبر أي CLI لنموذج ذكاء اصطناعي | 229 |
| tower_insights.py + network_intelligence.py | مؤشرات قابلة للتفسير من التاريخ | 335 |

المتنبئ نموذج Gradient Boosting تدرب على 3,345 عينة حقيقية.
خطؤه المطلق المتوسط 0.694 ديسيبل في التنبؤ بقيمة SINR بعد 3 دقائق.
مؤشر ضغط البرج لا يخترع عدد مستخدمين: المودم لا يكشفه، فالمؤشر يشرح مكوناته (CQI وSINR وRSRQ) بدل رقم مزيف.

## أهم قرار في التصميم

**المشكلة:** تغيير تردد المودم يمر عبر نفس الوصلة التي قد يقتلها التغيير.
تردد خاطئ يعني انقطاع الإنترنت، ولا سبيل للتراجع عن بعد.

**القرار:** كل تجربة تردد تمر عبر `guarded_band_experiment`.
يحفظ الإعداد الأصلي، يطبق التغيير، ثم يراقب عودة الاتصال الفعلي حتى 90 ثانية.
الاسترجاع يجري داخل `finally` مع إعادة محاولة وتحقق، فيعمل حتى لو انهارت جلسة المودم أثناء التطبيق.

**التكلفة/العائد:** كل تجربة أبطأ بما يصل إلى دقيقة ونصف.
المقابل: لا يبقى المودم عالقاً على تردد ميت وأنت خارج البيت.

## التشغيل

```
pip install -r requirements.txt
playwright install chromium
copy .env.example .env    ثم املأ عنوان بوابة المودم وكلمة المرور
run_project.bat
```

كلمة مرور المودم وعنوانه يعيشان في `.env` فقط، ولا يوجد أي منهما في الكود.
اللوحة تفتح على `http://<عنوان-جهازك>:8000/dashboard.html` من أي جهاز في الشبكة.
`allow_firewall.bat` يفتح المنفذ للأجهزة الأخرى، و`watchdog.bat` يعيد التشغيل عند التعليق.

إثبات أنه يعمل — 5 اختبارات دخان تعمل بلا مودم وبلا أي تبعية خارجية:

```
$ python smoke_test_db.py && python smoke_test_tower_insights.py &&
  python smoke_test_intelligence.py && python smoke_test_stability.py &&
  python smoke_test_telegram.py
SMOKE OK
TOWER INSIGHTS SMOKE OK
INTELLIGENCE SMOKE OK
STABILITY SMOKE OK
SMOKE TG OK
```
